## 1. 项目定位与理念

### 是什么

- 工作名：PrefrontalCortexGame（前额叶训练场）
- 类型：移动端认知训练小游戏合集
- 形态：一个 hub 首页 + 11 个独立小游戏，**用户自己选择玩什么**；Hub 顶部有「今日一练」轻入口（按日历日确定性挑一关）
- 引擎：Godot 4.7+，纯 GDScript，无外部依赖，竖屏 720×1280 基准

### 核心理念（不可妥协）

前三条管「这是什么产品」，第四条管「这关值不值得留」。

1. **每个游戏只练一种执行功能。** 前额叶管执行功能（自控、专注、计划、决策、抑制冲动）。每个游戏直接对应一个认知科学里真实存在的任务范式，练的就是那个范式练的东西，不混装。
2. **诚实标注。** 游戏只练「该能力在游戏内的熟练度」，不承诺迁移到现实、不承诺变聪明。神经可塑性需要数周数月；游戏提供的是「练习场」，不是「修复」。
3. **拒绝营销话术。** 文案中禁用：「3 分钟修复大脑」「激活 CEO」「多巴胺戒断」「变聪明」「左脑右脑开发」。每个游戏入口用一句平实的功能描述（如「抑制控制 · 干扰」）。
4. **要有挑战，能进心流。** 一直有事做、对错立刻知道、难度跟着水平涨、失败是你的失误不是运气。实验室范式成立不等于好玩：延迟折扣（棉花糖）空等加随机失败，已从清单拿掉。

两条打架时（范式成立但玩法是空等），**宁可换关，不要硬把流程搬上手机**。手感层面的模型、出处和十条清单见 [game-design.md](game-design.md)。

### 做一关的检查单

合入或改关前逐条过：

- 玩家随时知道现在要干什么
- 每一次操作立刻有反馈
- 没有大段空等
- 熟了以后题会变难，不是永远同一档
- 一种冲突就够，不要两套规则叠在一起
- 名字和说明只说这一关在练什么

| --- | --- | --- |

## 2. 架构

### 结构总览

```text
prefrontal-cortex-game/
├── project.godot     # main_scene = scenes/Hub.tscn；竖屏 720×1280
├── scenes/           # 每个场景只有根 Control + 脚本，节点树全部由代码构建
│   ├── Hub.tscn
│   ├── Stroop.tscn
│   ├── Schulte.tscn
│   ├── Dots.tscn
│   ├── NBack.tscn
│   ├── Switch.tscn
│   ├── Track.tscn
│   ├── Hanoi.tscn
│   ├── Corsi.tscn
│   ├── RuleShift.tscn
│   ├── RunningSpan.tscn
│   └── SelfOrder.tscn
├── scripts/
│   ├── GameBase.gd   # 所有游戏继承的脚手架
│   ├── Hub.gd        # GAMES 数组 = 游戏注册表
│   └── （每个游戏一个脚本）
└── docs/design.md    # 本文档
```

### 架构决策

- **场景文件只是壳。** .tscn 里只有 `Control` 根节点 + 脚本引用；所有 UI 节点在 `_ready()` 里用代码构建。这延续了同仓库 DodgeShotLab 的做法，避免编辑器二进制状态和代码漂移，diff 干净。
- **GameBase 提供公共外壳。** 深色背景（`#0d1220`）、左上角「< 返回」、右上角静音切换（「声」/「静」，全局状态存 `user://settings.cfg`）与「?」玩法、居中标题。子类在 `_init()` 里设 `title_text` 和 `help_text`，并重写 `_build_game()`。打开玩法时暂停游戏树，避免计时在说明底下继续跑。系统返回键 / Esc：玩法打开时先关掉说明，否则回到 Hub；Hub 上连续按两次退出。内置纯代码合成的轻量音效（`AudioStreamWAV` 正弦包络短音，无外部音频文件）与移动端短振感（`Input.vibrate_handheld`），静音或 headless 下自动跳过。答对/答错用 `_burst_feedback` 打出全屏大字 + 色闪 + 音效；无 burst 的点选动作调用 `_play_sfx`。记住关卡的游戏用同一套进度门：`_show_progress_gate` / `_on_progress_continue` / `_on_progress_fresh`（绿钮进最新一关，灰钮从头开始，且**选从头开始不会抹掉已存的历史最高档**）。通用结构化结算卡：`_show_summary_card` / `_hide_summary_card`，支持 1–2 个操作按钮（如再来一局 / 切换难度）。汉诺塔、追踪异色球、舒尔特方格、积木跨度、末项记、各点一次已接进度门；反向色字复用同一套 UI 选简单/困难。规则变了不需要进度门。新关照抄，不要另做一套选择 UI。改某一关后对照 [improvements.md](improvements.md) 该关一节更新现状和勾选。
- **Hub 用数据驱动注册。** `GAMES` 数组是唯一注册点：`{title, func, group, scene, built}`。列表按 `group`（执行功能）分段；卡片左侧两行（游戏名 + 练什么），右侧展示已玩关卡的客观历史进度/最佳成绩（未玩过则留白），顶部右上角提供全局「音效 / 静音」切换。未实现的游戏 `built: false` → 置灰并在右侧标「即将推出」，功能说明仍可见；实现后翻成 `true` 并填 `scene` 路径即可。列表卡片是可滚动的 `HubCard`（不是普通 Button）：在卡片上拖过阈值会滚动列表，轻点才进关；鼠标滚轮 / 触控板平移同样有效。
- **游戏间零耦合。** 每个游戏一个场景 + 一个脚本，返回即 `change_scene_to_file` 回 hub，无共享运行时状态。本地成绩各自存 `user://*.cfg`。
- **Hub 检查 GitHub Release。** 进首页时请求 `releases/latest`，远程 tag 比 `application/config/version` 新则底部提示「有新版本」；点开浏览器下载页。失败静默；点 × 记下该 tag，不再提示。不自动安装。

### 代码规范（沿用本仓库惯例）

- GDScript，`class_name` 不使用，场景脚本用 `extends` + 文件名即类
- 每个函数前一行 `##` 文档注释（DodgeShotLab 风格）
- 常量全大写、`const`，可调数值集中在脚本顶部
- 颜色统一十六进制 `Color("#rrggbb")`；共享调色板见 §6
- 中文界面文案（按钮、状态、标题），代码注释可中可英
- UI 节点代码构建时用 `set_anchors_and_offsets_preset` 做锚点布局，位置类用固定像素（竖屏基准 720 宽）

## 3. 如何新增一个游戏（五步）

以「N-Back」为例：

1. **写脚本** `scripts/NBack.gd`：

```gdscript
extends "res://scripts/GameBase.gd"
## N-Back：判断当前刺激是否与 N 步前相同。


const LIVES := 3

var score := 0

func _init() -> void:
    title_text = "N-Back"
    help_text = "判断当前刺激是否与 N 步前相同。"

func _build_game() -> void:
    # 构建 HUD、主内容、按钮，并开始第一试次
    pass
```

2. **建场景** `scenes/NBack.tscn`（内容三行，照抄改 id 和脚本路径）：

```text
[gd_scene load_steps=2 format=3]

[ext_resource type="Script" path="res://scripts/NBack.gd" id="1_nback"]

[node name="NBack" type="Control"]
script = ExtResource("1_nback")
```

3. **注册进 hub**：`scripts/Hub.gd` 的 `GAMES` 数组里找到对应条目，填 `scene` 路径、`built: true`。
4. **headless 验证**：

```bash
GODOT="/Applications/Godot.app/Contents/MacOS/Godot"
PROJ="<项目路径>"
"$GODOT" --headless --path "$PROJ" res://scenes/NBack.tscn --quit-after 5 2>&1 | grep -iE "error|invalid|failed|nonexistent|cannot|parse"
```

   无输出 = 通过。（经验：`add_theme_font_color_override` 不是真实 API，正确的是 `add_theme_color_override`。）
5. **肉眼验证 UI**：编辑器 F5，进游戏点几轮，确认布局、反馈、返回。对照 §1「做一关的检查单」（空等、反馈、难度会涨）。

## 5. 各游戏规格

### 5.1 反向色字 Stroop ✅ 已实现

**玩法**：中央是有颜色的字。多数试次字义与字体颜色不同，偶有一致。点选项上**写着字体颜色名**的按钮。进场用进度门选简单或困难。

**已实现规格**（`scripts/Stroop.gd`）：

- 颜色集合：红 / 蓝 / 绿 / 黄。题目：放大的彩色字。要点的是字体颜色对应的名字
- 约 12% **一致试次**（字=色），其余冲突；抑制仍必要，避免「永远反着读」
- 进场用 GameBase 进度门：绿钮简单、灰钮困难。局内重开保持当前难度
- 简单：选项灰底黑字，每题只重排位置；困难：黑色颜色名 + 与字义不同的底色（干扰），字和底色都重排
- 每答完一题，四个选项位置都会变
- **局内连对加速**：每题时限从 2.5s 起，每 4 连 −0.08s，下限约 0.9s；点错/超时 +0.05s（不超过 2.5）。倒计时条剩余 <25% 变红；HUD 常显当前「每题 x.xx 秒」
- 时限 ≤1.1s 时关掉全屏 burst，只留短提示，避免挡下一题
- 试次间隔 0.35s：答对/点错/超时后锁输入；超时不会在同一帧连扣生命
- 常显提示「点选项上的字，对上题目字的颜色」；答对显示加分，点错/超时分别提示
- 计分：答对 10 分 +（剩余/时限）×5 速度分 + 连击加成（每连击 +2，封顶 +20）。点错/超时 −10 分（不低于 0）并扣命，避免速度分诱导乱点
- 生命 3 次，错误/超时扣 1 并断连击；归零结束弹出结构化结算卡（得分、最佳连击、正确率、平均反应、本难度历史最佳），提供「再来一局」与「切换难度」按钮，隐藏底部四宫格避免重叠；本地 `user://stroop_best.cfg` 按简单/困难分开存 `easy_score` / `hard_score`（兼容旧 `score`）
- 响应式布局（`_layout_board()` 接 `NOTIFICATION_RESIZED`），题卡、提示条、倒计时条、四宫格随视口比例排布，无遮挡
- 参数集中在脚本顶部 `const`，可直接调

**已落地调优**：错题 −10（v1.4.0）、响应式布局 + 分难度最佳分 + 结算卡与切换难度（v1.8.1）。困难模式是否又变成对色、简单是否太易仍待实玩（见 §8）。

### 5.2 舒尔特方格 Schulte ✅ 已实现

**玩法**：网格随机排数字，从 1 起按顺序点，越快越好。通关后格子变多；档间插入轻松 4×4。

**已实现规格**（`scripts/Schulte.gd`）：

- 档位 5×5 → 6×6 → 7×7（1–25 / 1–36 / 1–49）。点完当前档约 0.7s 后先上一局 **4×4 呼吸关**（锯齿：先松再紧），再进下一档；7×7 通关后也会插一局 4×4，然后重排 7×7
- 呼吸关不改进度档位（`latest_size` 仍是 5–7）；可单独记 4×4 最佳
- 首次点击开始本档计时；点对该格绿色闪一下再禁用，点错计数 + 红色闪烁（不中断流程）
- HUD 常显「N×N  下一个 k／总数」（呼吸关带「呼吸关」前缀）；点错过才附加失误次数；每档单独计时、单独记最佳
- 格子边长按窗口可用空间计算（约 36–120px），重开按钮跟在网格下方；窗口拉伸会重排
- 本地记住历史最高档（`maxi` 只升不降）；再进时用 GameBase 进度门选「进入最新一关」或「从头开始」（5×5，不覆盖历史最高档）；本地存 `user://schulte_best.cfg`（兼容旧的 5×5 `best.time`）
- 「重新开始」重排当前档；若刚好点完、下一档还没出来，则直接进下一档
- **不做**限时点完出局模式（与刷最快纪录 UX 冲突）；限时仍待评估

### 5.3 看点数 Dots ✅ 已实现

**玩法**：屏幕短时间闪现随机分布的若干圆点，消失后用数字键盘输入看到的点数。

**已实现规格**（`scripts/Dots.gd`）：

- 一局 60 秒街机倒计时（开局 1 秒「准备」不扣时间），时间到结束；本地存最佳分 `user://dots_best.cfg`
- 点数 4–12 起步；答对先把闪现时间从 0.6s 每次 −0.02s（下限 0.35s），触底后点数上限 +1，不封顶；答错反向降难度
- 计分：正好 10 分 + 连击加成（每连击 +2，封顶 +20）；误差 ±1 给 5 分（半分，不升难度、不断连击）；误差 ≥2 断连击并降难度
- 点位用 Bridson 泊松盘铺满卡片，点间距约 3.8 倍半径；圆心限制在圆角+描边以内，整颗圆不出框；半径 9–14px
- UI：圆角卡片 + 闪现进度条；底部 0–9 + 删除 + 确定，非输入阶段键盘变淡；桌面可用键盘数字/退格/回车；面板和键盘随窗口重排
- 答对回显 0.7 秒、答错（含接近）回显 1.8 秒（点改成对/错色，中间写出实际数量），再清空 0.2 秒显示「下一题」，对答案阶段不扣 60 秒

### 5.4 反向反应 GoNoGo — v1.8.0 已从可玩列表移除

**曾做的玩法**：屏幕陆续出现彩色圆。默认「绿圆→点它，红圆→别点」。连对约 6–9 次后规则反转（红点绿停）。对应 Go/No-Go 范式，已在较早版本实现并上线。

v1.8.0 收瘦套装时拿掉：与反向色字同属「看刺激再点/忍」的抑制关，手感重叠。脚本 `GoNoGo.gd` 已从本版仓库移除，本地成绩文件 `user://gonogo_best.cfg` 不再读取。

### 5.5 红灯停 StopSignal — v1.8.0 已从可玩列表移除

**曾做的玩法**：小车从左开向终点线，靠近绿线之后才能冲；约一半轮次在冲刺窗口前突然亮红灯，亮了就必须停手。对应 Stop-signal 范式，已在较早版本实现并上线。

v1.8.0 按用户要求从可玩列表拿掉。脚本 `StopSignal.gd` 已从本版仓库移除，本地成绩文件 `user://stopsignal_best.cfg` 不再读取。

### 5.6 N-Back ✅ 已实现

**玩法**：3×3 宫格依次亮一个位置，判断是否与 N 步前相同。点「相同」或「不同」。

**已实现规格**（`scripts/NBack.gd`）：

- N=2 起步，封顶 4，下限 2；刺激间隔 SOA 1.8s（亮 0.8s，其余作答窗口）
- 开始前 N 步只记位置、不判分；之后答对 +10；一局固定 45 道计分题（不再三命速死）
- 「相同」试次约 30%；连对 6 升 N，连错 3 降 N
- 对/错反馈标在刚亮的那一格（绿/红）并配轻量正/负音效；结束展示结构化结算卡（得分、最高到达 N-Back、正确率、平均反应、历史最佳）
- HUD 常显「N-Back · 往前第 N 个」与题号进度；开局先说明，点「开始」后才出题；本地存 `user://nback_best.cfg`
- 桌面可用 F/左 = 相同，J/右 = 不同
- Dual N-Back（颜色/声音混装）仍不做

### 5.7 任务切换 Switch ✅ 已实现

**玩法**：中央数字 1–9（无 5），上方色块是规则：蓝=奇偶，橙=大于/小于 5。

**已实现规格**（`scripts/Switch.gd`）：规则每 1–3 试次切换；重复答对 +10，切换答对 +20；每题时限开局 1.6s，随连对收到约 0.9s；生命 3；HUD 常显「距切换 N 题」（本规则还剩几题，含本题；环境提示，不要求跨题记数）；结束展示结构化结算卡（得分、历史最佳、总正确率、切换正确率、切换耗时 ms）；本地最佳分。

### 5.8 追踪异色球 Track ✅ 已实现

**玩法**：黄球高亮 1.5s，全部变蓝后乱跑，停下点出原来的异色球。

**已实现规格**（`scripts/Track.gd`）：6–12 球，异色 1–3（满 12 后 `beyond_cap` 可加异色至最多 5，并缩小半径，**不再加长移动**）；移动时间 = `clamp(4.0 + 0.5×(球数−6), 4.0, 8.0)`（按最多 12 球封顶，6 球 4.0s 起递增至 12 球 7.0s）；高亮约 1.5s 起、随球数略减（下限 0.9s）；移速 270–420 像素/秒；初始方向避开横竖轴各 20°；边界反弹无球间碰撞；点选限时 **3 秒**，超时当漏选；全对 +20 并加球；错/漏/超时扣命；本地记住历史最高球数（从头开始不覆盖），再进时选「进入最新一关」或「从头开始」（6 个球），进度门与汉诺塔同一套 UI；本地最佳分。

### 5.9 中间箭头 Flanker — v1.8.0 已从可玩列表移除

**曾做的玩法**：一排箭头，只点最中间那个的方向；两侧常常指向反方向。对应 Eriksen Flanker 范式，已在较早版本实现并上线（60 秒计时局、中间箭更大更亮）。

v1.8.0 收瘦套装时拿掉：与反向色字同属抑制控制街机，手感重叠。脚本 `Flanker.gd` 已从本版仓库移除。延迟折扣（棉花糖）更早从清单拿掉，与这次无关。

### 5.10 汉诺塔 Hanoi ✅ 已实现

**玩法**：三柱移盘，点来源再点目标；大不能压小。

**已实现规格**（`scripts/Hanoi.gd`）：3 盘起，**仅最优**通关 +1 盘封顶 6；基础分 N×30，最优再 +N×50；步数 ≤ 最优×1.5 的非最优可过本关但不加盘；**超过最优×1.5 不算过关**，必须复位重来（堵住混过）；过关后展示最优路径（左/中/右）；用时只展示，**无限时、无随机失败**；底部「复位」把盘子收回左柱并清零本关步数（总分保留）；本地记住历史最高盘数（从头开始不覆盖），再进时用 GameBase 进度门选「进入最新一关」或「从头开始」（3 盘）；本地最佳分。


### 5.11 积木跨度 Corsi ✅ 已实现

**玩法**：3×3 九个方块按顺序亮起；看完后按相同顺序点回去。练空间序列工作记忆（跨度），与 N-Back（更新/匹配）、看点数（瞬时计数）不同。

**已实现规格**（`scripts/Corsi.gd`）：

- 一局约 **60 秒**街机倒计时；时间到结算
- 开局跨度 3；全对 +1（上限 9），点错 −1（下限 2）；序列内不允许连亮同一格
- 演示：每格亮约 0.55s、间隔约 0.18s；点选阶段逐步闪绿，点错闪红并结束本轮
- 计分：10 + 跨度×4 + 连对加成；本地存 `user://corsi_best.cfg`（最佳分 + 历史最长跨度）
- 历史跨度 > 3 时进场用 GameBase 进度门：继续最长跨度或从 3 重来
- **不做** Dual N-Back；不加第二套规则


### 5.12 规则变了 RuleShift ✅ 已实现

**玩法**：上方刺激卡片有颜色 / 形状 / 数量；下方三堆各只在一个维度上与之匹配。按当前**隐藏规则**点对的那一堆。规则会在若干次答对后切换，只提示「规则变了」，不告知新维度。与「任务切换」（蓝/橙明示规则）区分开。

**已实现规格**（`scripts/RuleShift.gd`）：

- 三维各 3 值：红/蓝/绿，●/■/▲，1/2/3；每题三堆分别只匹配色 / 形 / 数，且**每题打乱三堆左右位置**（禁止固定左=色/中=形/右=数，防位置作弊）
- 隐藏规则在色/形/数间切换；连续答对 4–7 次后换规则并大字提示「规则变了」
- 一局约 **60 秒**；每题时限开局 3.2s，连对收到约 1.6s；点错/超时断连击并略放宽
- 计分：答对 10 + 连对加成；刚换规则后的首次答对额外 +10；结束展示结构化结算卡（得分、成功切规则次数、正确率、平均反应、历史最佳）；本地 `user://ruleshift_best.cfg`
- **不做**完整 WCST 多规则堆叠、不加第四维度；无账号 / 通知

### 5.13 线索靶 AxCpt — v1.8.0 已从可玩列表移除

**曾做的玩法**：每题先出「前字」（甲/乙），短间隔后再出「后字」（靶/他）；只有「甲 → 靶」点「是」。对应 AX-CPT（Braver 主动/反应控制），已在 v1.5.0 实现并上线。

v1.8.0 收瘦套装时拿掉：与留下的注意关（搜索/追踪）以及抑制关同属「看一下、点一下」实验室任务，手感容易撞车。脚本 `AxCpt.gd` 已从本版仓库移除，本地成绩文件 `user://axcpt_best.cfg` 不再读取。


### 5.14 末项记 RunningSpan ✅ 已实现

**玩法**：数字 1–9 一条条闪过；串比「末项数 N」更长。串结束后，按从早到晚的顺序点出**最后 N 个**。前面的要主动丢掉。与积木跨度（整段空间顺序复述）、N-Back（当前是否与 N 步前相同）区分开。

**已实现规格**（`scripts/RunningSpan.gd`）：

- 范式：Running Span / running memory（工作记忆更新）
- 末项 N 从 2 起，全对 +1（最多 7），点错 −1（最少 2）；串长 = N + 随机 1–3
- 显示约 0.75→0.50s（随连对）；数字间间隔 0.18s；一局约 **60 秒**
- 进场进度门（历史最长末项 > 2）；本地 `user://running_span_best.cfg`
- 计分：全对 10 + N×5 + 连对加成；错断连击并略降 N
- **不做** Dual N-Back、不加听觉通道、不做 Digit Span 整段复述（与积木跨度同属跨度复述）
- **v1.6.1 QA：** 帮助文案「末项」与 HUD 对齐；末项序列用显式拷贝写入 typed 数组（避免 `slice` 赋值类型问题）

### 5.15 各点一次 SelfOrder ✅ 已实现

**玩法**：一组彼此不同的图案。每次点一个还没点过的；点完后同样的图案会换位置，再点下一个没点过的。点到已经点过的，这一轮结束。练的是自己监控「点过哪些」，而不是复述给定顺序。

**已实现规格**（`scripts/SelfOrder.gd`）：

- 范式：Self-Ordered Pointing（Petrides & Milner, 1982）；图案换位，避免靠位置记
- 一局约 **60 秒**；开局 4 个，全对 +1（最多 12），点错 −1（最少 4）
- 每点对一个（尚未点完）+4；全部点完再加 10 + 个数×4 + 连对加成；点错断连击并短时揭示已点过的
- 点对后图案换到新位置（至少一半会动）；图案用形状+颜色双重区分，几何绘制，不依赖特殊字体
- 历史最多一次点完的个数 > 4 时进场用 GameBase 进度门；本地 `user://selforder_best.cfg`
- 与积木跨度区分：不是按给定顺序复述，顺序由玩家自己选，且位置每次打乱
- **不做** Dual N-Back、不加第二任务、不做 Digit Span 整段复述

**v1.7.0 同时落地的 QA：** 游戏内系统返回键 / Esc 回到 Hub（玩法打开时先关闭说明）；Hub 连续按两次返回退出。补齐此前未入库的脚本 `.uid`。

## 9. 明确不做（当前版本）
