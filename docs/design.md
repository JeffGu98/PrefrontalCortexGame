> 十关手感问题与逐关改进清单见 [improvements.md](improvements.md)。

## 1. 项目定位与理念

### 是什么

- 工作名：PrefrontalCortexGame（前额叶训练场）
- 类型：移动端认知训练小游戏合集
- 形态：一个 hub 首页 + 12 个独立小游戏，**用户自己选择玩什么**
- 引擎：Godot 4.7+，纯 GDScript，无外部依赖，竖屏 720×1280 基准

### 核心理念（不可妥协）

前三条管「这是什么产品」，第四条管「这关值不值得留」。

1. **每个游戏只练一种执行功能。** 前额叶管执行功能（自控、专注、计划、决策、抑制冲动）。每个游戏直接对应一个认知科学里真实存在的任务范式，练的就是那个范式练的东西，不混装。
2. **诚实标注。** 游戏只练「该能力在游戏内的熟练度」，不承诺迁移到现实、不承诺变聪明。神经可塑性需要数周数月；游戏提供的是「练习场」，不是「修复」。
3. **拒绝营销话术。** 文案中禁用：「3 分钟修复大脑」「激活 CEO」「多巴胺戒断」「变聪明」「左脑右脑开发」。每个游戏入口用一句平实的功能描述（如「抑制控制 · 干扰」）。
4. **要有挑战，能进心流。** 一直有事做、对错立刻知道、难度跟着水平涨、失败是你的失误不是运气。实验室范式成立不等于好玩：延迟折扣（棉花糖）空等加随机失败，已从清单拿掉。

两条打架时（范式成立但玩法是空等），**宁可换关，不要硬把流程搬上手机**。手感层面的模型、出处和十条清单见 [game-design.md](game-design.md)。

### 做一关的检查单

合入或改关前逐条过：

- 玩家随时知道现在要干什么
- 每一次操作立刻有反馈
- 没有大段空等
- 熟了以后题会变难，不是永远同一档
- 一种冲突就够，不要两套规则叠在一起
- 名字和说明只说这一关在练什么

### 认知科学依据（选型来源）

| 执行功能 | 有依据的范式 | 不采用的流行说法 |
| --- | --- | --- |
| 抑制控制 | Stroop、Go/No-Go、Stop-signal、Flanker | —— |
| 注意 | 舒尔特方格、多目标追踪（MOT） | 「专注力音乐」 |
| 工作记忆 | N-Back、Corsi 积木跨度、瞬时计数（subitizing） | Dual N-Back（混装，不做） |
| 认知灵活性 | 任务切换（有线索）、WCST 风格规则推断（无线索） | —— |
| 计划 | 汉诺塔（Tower of Hanoi） | —— |

正念、睡眠、运动对前额叶最有效但属于生活干预，做不成街机机制，**不在游戏清单内**。

## 2. 架构

### 结构总览

```text
prefrontal-cortex-game/
├── project.godot     # main_scene = scenes/Hub.tscn；竖屏 720×1280
├── scenes/           # 每个场景只有根 Control + 脚本，节点树全部由代码构建
│   ├── Hub.tscn
│   ├── Stroop.tscn
│   ├── Schulte.tscn
│   ├── Dots.tscn
│   ├── GoNoGo.tscn
│   ├── StopSignal.tscn
│   ├── NBack.tscn
│   ├── Switch.tscn
│   ├── Track.tscn
│   ├── Flanker.tscn
│   ├── Hanoi.tscn
│   ├── Corsi.tscn
│   └── RuleShift.tscn
├── scripts/
│   ├── GameBase.gd   # 所有游戏继承的脚手架
│   ├── Hub.gd        # GAMES 数组 = 游戏注册表
│   └── （每个游戏一个脚本）
└── docs/design.md    # 本文档
```

### 架构决策

- **场景文件只是壳。** .tscn 里只有 `Control` 根节点 + 脚本引用；所有 UI 节点在 `_ready()` 里用代码构建。这延续了同仓库 DodgeShotLab 的做法，避免编辑器二进制状态和代码漂移，diff 干净。
- **GameBase 提供公共外壳。** 深色背景（`#0d1220`）、左上角「< 返回」、右上角「?」玩法、居中标题。子类在 `_init()` 里设 `title_text` 和 `help_text`，并重写 `_build_game()`。打开玩法时暂停游戏树，避免计时在说明底下继续跑。答对/答错用 `_burst_feedback` 打出全屏大字 + 色闪，避免只靠一行小提示。记住关卡的游戏用同一套进度门：`_show_progress_gate` / `_on_progress_continue` / `_on_progress_fresh`（绿钮进最新一关，灰钮从头开始）。汉诺塔、追踪异色球、舒尔特方格、积木跨度已接；反向色字复用同一套 UI 选简单/困难。规则变了不需要进度门。新关照抄，不要另做一套选择 UI。改某一关后对照 [improvements.md](improvements.md) 该关一节更新现状和勾选。
- **Hub 用数据驱动注册。** `GAMES` 数组是唯一注册点：`{title, func, group, scene, built}`。列表按 `group`（执行功能）分段；卡片两行（游戏名 + 练什么）。未实现的游戏 `built: false` → 置灰并在右侧标「即将推出」，功能说明仍可见；实现后翻成 `true` 并填 `scene` 路径即可。
- **游戏间零耦合。** 每个游戏一个场景 + 一个脚本，返回即 `change_scene_to_file` 回 hub，无共享运行时状态。本地成绩各自存 `user://*.cfg`。
- **Hub 检查 GitHub Release。** 进首页时请求 `releases/latest`，远程 tag 比 `application/config/version` 新则底部提示「有新版本」；点开浏览器下载页。失败静默；点 × 记下该 tag，不再提示。不自动安装。

### 代码规范（沿用本仓库惯例）

- GDScript，`class_name` 不使用，场景脚本用 `extends` + 文件名即类
- 每个函数前一行 `##` 文档注释（DodgeShotLab 风格）
- 常量全大写、`const`，可调数值集中在脚本顶部
- 颜色统一十六进制 `Color("#rrggbb")`；共享调色板见 §6
- 中文界面文案（按钮、状态、标题），代码注释可中可英
- UI 节点代码构建时用 `set_anchors_and_offsets_preset` 做锚点布局，位置类用固定像素（竖屏基准 720 宽）

## 3. 如何新增一个游戏（五步）

以「N-Back」为例：

1. **写脚本** `scripts/NBack.gd`：

```gdscript
extends "res://scripts/GameBase.gd"
## N-Back：判断当前刺激是否与 N 步前相同。


const LIVES := 3

var score := 0

func _init() -> void:
    title_text = "N-Back"
    help_text = "判断当前刺激是否与 N 步前相同。"

func _build_game() -> void:
    # 构建 HUD、主内容、按钮，并开始第一试次
    pass
```

2. **建场景** `scenes/NBack.tscn`（内容三行，照抄改 id 和脚本路径）：

```text
[gd_scene load_steps=2 format=3]

[ext_resource type="Script" path="res://scripts/NBack.gd" id="1_nback"]

[node name="NBack" type="Control"]
script = ExtResource("1_nback")
```

3. **注册进 hub**：`scripts/Hub.gd` 的 `GAMES` 数组里找到对应条目，填 `scene` 路径、`built: true`。
4. **headless 验证**：

```bash
GODOT="/Applications/Godot.app/Contents/MacOS/Godot"
PROJ="<项目路径>"
"$GODOT" --headless --path "$PROJ" res://scenes/NBack.tscn --quit-after 5 2>&1 | grep -iE "error|invalid|failed|nonexistent|cannot|parse"
```

   无输出 = 通过。（经验：`add_theme_font_color_override` 不是真实 API，正确的是 `add_theme_color_override`。）
5. **肉眼验证 UI**：编辑器 F5，进游戏点几轮，确认布局、反馈、返回。对照 §1「做一关的检查单」（空等、反馈、难度会涨）。

## 5. 各游戏规格

### 5.1 反向色字 Stroop ✅ 已实现

**玩法**：中央是有颜色的字，字义和字体颜色一定不同。点选项上**写着字体颜色名**的按钮。进场用进度门选简单或困难。

**已实现规格**（`scripts/Stroop.gd`）：

- 颜色集合：红 / 蓝 / 绿 / 黄。题目：放大的彩色字，字义与字体颜色始终不同。要点的是字体颜色对应的名字
- 进场用 GameBase 进度门：绿钮简单、灰钮困难。局内重开保持当前难度
- 简单：选项灰底黑字，每题只重排位置；困难：黑色颜色名 + 与字义不同的底色（干扰），字和底色都重排
- 每答完一题，四个选项位置都会变
- 每题固定 2.5 秒，倒计时条剩余 <25% 变红；超时视同错误；点选项会回弹，不停留在按下发灰态
- 试次间隔 0.35s：答对/点错/超时后锁输入，避免连点吃掉下一题；超时不会在同一帧连扣生命
- 常显提示「点选项上的字，对上题目字的颜色」；答对显示加分，点错/超时分别提示
- 计分：答对 10 分 + 剩余秒数×5 速度分 + 连击加成（每连击 +2，封顶 +20）。错题只扣命、不扣分
- 生命 3 次，错误/超时扣 1 并断连击；归零结束，可重开；本地存 `user://stroop_best.cfg`
- 参数集中在脚本顶部 `const`，可直接调

**已知的后续调优点**：速度分是否诱导乱点，仍待实玩验证（见 §8）。

### 5.2 舒尔特方格 Schulte ✅ 已实现

**玩法**：网格随机排数字，从 1 起按顺序点，越快越好。通关后格子变多；档间插入轻松 4×4。

**已实现规格**（`scripts/Schulte.gd`）：

- 档位 5×5 → 6×6 → 7×7（1–25 / 1–36 / 1–49）。点完当前档约 0.7s 后先上一局 **4×4 呼吸关**（锯齿：先松再紧），再进下一档；7×7 通关后也会插一局 4×4，然后重排 7×7
- 呼吸关不改进度档位（`latest_size` 仍是 5–7）；可单独记 4×4 最佳
- 首次点击开始本档计时；点对该格绿色闪一下再禁用，点错计数 + 红色闪烁（不中断流程）
- HUD 常显「N×N  下一个 k／总数」（呼吸关带「呼吸关」前缀）；点错过才附加失误次数；每档单独计时、单独记最佳
- 格子边长按窗口可用空间计算（约 36–120px），重开按钮跟在网格下方；窗口拉伸会重排
- 本地记住当前档；再进时用 GameBase 进度门选「进入最新一关」或「从头开始」（5×5）；本地存 `user://schulte_best.cfg`（兼容旧的 5×5 `best.time`）
- 「重新开始」重排当前档；若刚好点完、下一档还没出来，则直接进下一档
- **不做**限时点完出局模式（与刷最快纪录 UX 冲突）；限时仍待评估

### 5.3 看点数 Dots ✅ 已实现

**玩法**：屏幕短时间闪现随机分布的若干圆点，消失后用数字键盘输入看到的点数。

**已实现规格**（`scripts/Dots.gd`）：

- 一局 60 秒街机倒计时（开局 1 秒「准备」不扣时间），时间到结束；本地存最佳分 `user://dots_best.cfg`
- 点数 4–12 起步；答对先把闪现时间从 0.6s 每次 −0.02s（下限 0.35s），触底后点数上限 +1，不封顶；答错反向降难度
- 计分：正好 10 分 + 连击加成（每连击 +2，封顶 +20）；误差 ±1 给 5 分（半分，不升难度、不断连击）；误差 ≥2 断连击并降难度
- 点位用 Bridson 泊松盘铺满卡片，点间距约 3.8 倍半径；圆心限制在圆角+描边以内，整颗圆不出框；半径 9–14px
- UI：圆角卡片 + 闪现进度条；底部 0–9 + 删除 + 确定，非输入阶段键盘变淡；桌面可用键盘数字/退格/回车；面板和键盘随窗口重排
- 答对回显 0.7 秒、答错（含接近）回显 1.8 秒（点改成对/错色，中间写出实际数量），再清空 0.2 秒显示「下一题」，对答案阶段不扣 60 秒

### 5.4 反向反应 GoNoGo ✅ 已实现

**玩法**：屏幕陆续出现彩色圆。默认「绿圆→点它，红圆→别点」。连对约 6–9 次后规则反转（红点绿停），顶部色块同步改动词。

**已实现规格**（`scripts/GoNoGo.gd`）：

- 刺激显示从 1.0s 随连对收到约 0.55s，未反应即过；试次间隔 0.35–0.6s 随机；开局 1 秒准备
- Go 试次约 62%；连续 4 个 Go 后强制一个 No-Go，避免一直连点
- 规则反转窗口：每次反转后随机在连对 6–9 次时翻（`flip_at`）
- 计分：Go 命中 +10；No-Go 忍住 +15；误点 No-Go 或 Go 没点到都扣 1 命并断连击
- 生命 3 次，归零结束；本地存 `user://gonogo_best.cfg`
- 刺激弹出时圆和底部「点」按钮微微放大；非刺激阶段按钮变淡；桌面可用空格/回车
- 顶部常显规则色块：绿/红底上写「点」或「停」

### 5.5 红灯停 StopSignal ✅ 已实现

**玩法**：小车从左开向终点线，**靠近绿线之后**才能冲。约一半轮次在冲刺窗口前突然亮红灯，亮了就必须停手。

**已实现规格**（`scripts/StopSignal.gd`）：

- 行驶时长随连对从约 2.0s 收到约 1.0s（绿线仍在 72%）；Stop 试次 50%（`STOP_RATIO := 0.5`）；连续 2 个绿灯后强制红灯，且不连续出两次红灯
- 绿灯只有进度 ≥72%（绿线）才算冲过；提前点提示「还没到」，不给分、不扣命
- 红灯出现点随连对往绿线挤（约 40%→更靠近 68%），仍严格低于冲刺窗口；亮后忍住 0.5s 即算刹住；红灯期间点了扣命
- 计分：绿灯冲过 +10；红灯刹住 +20；绿灯没冲或红灯没刹都扣 1 命
- 生命 3 次；开局 1 秒准备；试次间隔 0.35–0.55s；本地存 `user://stopsignal_best.cfg`
- 赛道有绿线冲刺区 + 黄线终点；靠近绿线时「冲」按钮脉动加强；冲过车加亮、误冲红灯急闪

### 5.6 N-Back ✅ 已实现

**玩法**：3×3 宫格依次亮一个位置，判断是否与 N 步前相同。点「相同」或「不同」。

**已实现规格**（`scripts/NBack.gd`）：

- N=2 起步，封顶 4，下限 2；刺激间隔 SOA 1.8s（亮 0.8s，其余作答窗口）
- 开始前 N 步只记位置、不判分；之后答对 +10；一局固定 45 道计分题（不再三命速死）
- 「相同」试次约 30%；连对 6 升 N，连错 3 降 N
- 对/错反馈标在刚亮的那一格（绿/红），不只靠大字
- HUD 常显「N-Back · 往前第 N 个」与题号进度；开局先说明，点「开始」后才出题；本地存 `user://nback_best.cfg`
- 桌面可用 F/左 = 相同，J/右 = 不同
- Dual N-Back（颜色/声音混装）仍不做

### 5.7 任务切换 Switch ✅ 已实现

**玩法**：中央数字 1–9（无 5），上方色块是规则：蓝=奇偶，橙=大于/小于 5。

**已实现规格**（`scripts/Switch.gd`）：规则每 1–3 试次切换；重复答对 +10，切换答对 +20；每题时限开局 1.6s，随连对收到约 0.9s；生命 3；本地最佳分。

### 5.8 追踪异色球 Track ✅ 已实现

**玩法**：黄球高亮 1.5s，全部变蓝后乱跑，停下点出原来的异色球。

**已实现规格**（`scripts/Track.gd`）：6–12 球，异色 1–3（满 12 后 `beyond_cap` 可加异色至最多 5，并缩小半径，**不再加长移动**）；移动时间 = `(4+0.5×(球数−6)) × ⌈(15−球数)/2⌉`（按最多 12 球封顶，约 13–20 秒）；高亮约 1.5s 起、随球数略减（下限 0.9s）；移速 270–420 像素/秒；初始方向避开横竖轴各 20°；边界反弹无球间碰撞；点选限时 **3 秒**，超时当漏选；全对 +20 并加球；错/漏/超时扣命；本地记住当前球数，再进时选「进入最新一关」或「从头开始」（6 个球），进度门与汉诺塔同一套 UI；本地最佳分。

### 5.9 中间箭头 Flanker ✅ 已实现

**玩法**：一排箭头，只点最中间那个的方向。两侧常常指向反方向。

**已实现规格**（`scripts/Flanker.gd`）：Eriksen Flanker；一致 / 不一致试次；开局每题 1.15 秒，连对每 3 次 −0.05 秒，下限 0.52 秒；点错略放宽时限、断连击但不扣命；不一致比例随加速从 55% 升到 82%；间隔 0.22 秒；**一局约 60 秒**计时结算（不再用三命出局）；中间箭头略大略亮（字号 88 / 侧翼 64，色更白），不靠描边；加速到约 0.72s 以下关掉全屏大字 burst，只留中间变色 + 短提示；约 0.70s 以下改用 **7 箭**并收紧侧翼间距；本地最佳分。延迟折扣（棉花糖）已从清单拿掉：空等加随机失败进不了心流。

### 5.10 汉诺塔 Hanoi ✅ 已实现

**玩法**：三柱移盘，点来源再点目标；大不能压小。

**已实现规格**（`scripts/Hanoi.gd`）：3 盘起，**仅最优**通关 +1 盘封顶 6；基础分 N×30，最优再 +N×50；步数 ≤ 最优×1.5 的非最优可过本关但不加盘；**超过最优×1.5 不算过关**，必须复位重来（堵住混过）；过关后展示最优路径（左/中/右）；用时只展示，**无限时、无随机失败**；底部「复位」把盘子收回左柱并清零本关步数（总分保留）；本地记住当前盘数，再进时用 GameBase 进度门选「进入最新一关」或「从头开始」（3 盘）；本地最佳分。


### 5.11 积木跨度 Corsi ✅ 已实现

**玩法**：3×3 九个方块按顺序亮起；看完后按相同顺序点回去。练空间序列工作记忆（跨度），与 N-Back（更新/匹配）、看点数（瞬时计数）不同。

**已实现规格**（`scripts/Corsi.gd`）：

- 一局约 **60 秒**街机倒计时；时间到结算
- 开局跨度 3；全对 +1（上限 9），点错 −1（下限 2）；序列内不允许连亮同一格
- 演示：每格亮约 0.55s、间隔约 0.18s；点选阶段逐步闪绿，点错闪红并结束本轮
- 计分：10 + 跨度×4 + 连对加成；本地存 `user://corsi_best.cfg`（最佳分 + 历史最长跨度）
- 历史跨度 > 3 时进场用 GameBase 进度门：继续最长跨度或从 3 重来
- **不做** Dual N-Back；不加第二套规则


### 5.12 规则变了 RuleShift ✅ 已实现

**玩法**：上方刺激卡片有颜色 / 形状 / 数量；下方三堆各只在一个维度上与之匹配。按当前**隐藏规则**点对的那一堆。规则会在若干次答对后切换，只提示「规则变了」，不告知新维度。与「任务切换」（蓝/橙明示规则）区分开。

**已实现规格**（`scripts/RuleShift.gd`）：

- 三维各 3 值：红/蓝/绿，●/■/▲，1/2/3；每题三堆分别只匹配色 / 形 / 数
- 隐藏规则在色/形/数间切换；连续答对 4–7 次后换规则并大字提示「规则变了」
- 一局约 **60 秒**；每题时限开局 3.2s，连对收到约 1.6s；点错/超时断连击并略放宽
- 计分：答对 10 + 连对加成；刚换规则后的首次答对额外 +10；本地 `user://ruleshift_best.cfg`
- **不做**完整 WCST 多规则堆叠、不加第四维度；无账号 / 通知

## 9. 明确不做（当前版本）

- 账号系统、云同步、排行榜对战

- 提醒通知、打卡系统（先验证游戏本身是否好玩）
- iOS / iPhone 安装包（发布只打 Android APK）
