# 十关手感审计与改进清单

> 对照 [design.md](design.md) 检查单和 [game-design.md](game-design.md) 十条，记录当前十关的问题和改进方向。
>
> **本文只规划，不代替产品规格。** 改某一关时：先读该关的 `design.md` §5 规格，再按本节动手；改完必须回头对照本页——已做的勾掉并改「现状」，没做的保持待做，手感条目不要因为顺手加了 UI/存档就悄悄勾掉。同时回写 `design.md` 该关规格。
>
> 约束不变：一个游戏一种功能、不混装、不吹牛。范式成立但空等 → 改手感，不叠第二种任务。
>
> 审计日期：2026-08-26。对照代码：2026-09-30（舒尔特数字格 5→6→7 + 进度门；动物切块已去掉）。

## 怎么改

一次只改一关。合入前对照 `design.md` §7：headless、F5 整局、hub 同步、检查单。

**每次改了哪一关，都打开本页该关一节和动手顺序表，逐条对比代码。** 不问「这次算不算手感」——UI、难度门、时限、反馈、存档都要过一遍。该更新就更新，对不上的以代码为准改文档，不要让本页停在上一版玩法。

两份文档打架时：产品身份听 `design.md`，手感听 `game-design.md` 和本页。

## 整套先修的三刀（跨关）

这些不是某一关独有。逐关改时能顺手带上的就带，不要单独开一个「重构全部生命系统」的大 PR，除非正在改那一关。

1. **三命容易掐断心流。** 刚热手就出局，技能原子还没串到下一档。街机关更适合「一局计时」或「错了略放宽、对了再收紧」。命可以留，但不要当唯一结束条件。
2. **难度曲线太平。** 文档要求锯齿：紧一段、松一口。多数关永远同一档 → 技能涨了、挑战不涨 → burnout。
3. **抑制控制四关手感撞车。** 色字 / 反向反应 / 中间箭头都是「看刺激、点左右、三命」。红灯停因车在动差异最大。四关都留，但节奏和冲突必须更不像。

MDA：机制都有了，动态（连击、加速、卡关）偏弱；体验几乎只吃 Challenge，Sensation 只有大字反馈。

**动手顺序（不换关、只改现有）：**

| 序 | 关 | 为什么先改 | 状态 |
| --- | --- | --- | --- |
| 1 | 反向反应 | 空档最长，最违反「无空等」 | 已改（GAP 0.35–0.6；Go≈62%；反转 6–9；显示 1.0→0.55） |
| 2 | 看点数 | 每题 2.3s 看答案，一分钟局里大量时间不玩 | 已改（对了 0.7s / 错了 1.8s；清空 0.2s） |
| 3 | 反向色字 | 连对加速，成本低、结构已是街机 | 已改玩法（进场简单/困难；简单灰底黑字；困难底色干扰；每题重排；固定 2.5 秒；点选项回弹；−10 未做） |
| 4 | 任务切换 | 同上，3 秒太松 | 已改（时限 1.6→0.9；切换每 1–3） |
| 5 | 红灯停 | 已经最好玩，补封顶 | 已改（文档 50%；行驶 2.0→1.0；红灯更晚；间隔 0.35–0.55） |
| 6 | 舒尔特 | 5×5 之后要有下一档 | 已改（数字格 5→6→7 + 进度门；动物切块已去掉；4×4 / 限时未做） |
| 7 | N-Back | 加快 SOA、让人摸到 3-Back | 已改（SOA 1.8；升 N=6；45 题；格子反馈；无 Dual） |
| 8 | 追踪异色球 | 点选限时 / 中段检查，避免纯旁观 | 已改（点选 3s；12 后异色+/缩小；移动不加时） |
| 9 | 中间箭头 | 已经自适应；加速后减弱 burst、考虑计时局 | 待做 |
| 10 | 汉诺塔 | 堵住非最优混过；不要街机化 | 待做 |

## 1. 反向色字 · Stroop

**规格：** `design.md` §5.1 · `scripts/Stroop.gd`  
**现状：** 题目是有颜色的字（字≠色）；点选项上的字对题目的字体颜色。进场进度门选简单（灰底黑字，每题仍重排位置）或困难（选项底色干扰，字和底都重排）。每题固定 2.5 秒。点选项缩放回弹，样式各态同一色，避免手机按下后卡灰。错题 −10 未做。连对加速未做。

| 检查项 | 现状 |
| --- | --- |
| 知道干什么 | 过关 |
| 立刻反馈 | 过关 |
| 无空等 | 基本过关 |
| 难度会涨 | **不过**：局内永远 2.5 秒、永远 4 色；简单/困难只在进场选一次 |
| 一种冲突 | 过关（困难才有底色干扰；简单只有字色冲突） |

**问题**

- 开局有 Challenge，几分钟后同一首歌。简单模式去掉底色干扰后更明显。
- 速度分可能诱导乱点（`design.md` §8 已记）。
- `_burst_feedback` 在 2.5 秒节奏里勉强；再加速会挡下一题。

**改进方向**

- 连对缩短时限：2.5 → 下限约 0.9，每 4 连 −0.08s，点错 +0.05s（抄中间箭头）。
- 不要加第五种颜色，不要再叠一套规则。
- 若实玩确认乱点：错题改为 −10，而不是只扣命。
- 可加极少量**一致试次**（字色相同），让「抑制」重新必要。现在 100% 冲突，大脑会改成「永远反着读」。这是范式内部变体，不是第二种功能。

- [x] 连对加速改为固定时限（先 2 秒，再按手感拉到 2.5 秒）
- [x] 题目：放大的彩色字（字≠色）；点选项的字 = 题目的字体颜色
- [x] 困难：选项底色作干扰，每题重排字和底
- [x] 进场简单/困难（简单灰底黑字，位置仍变；复用 GameBase 进度门）
- [x] 点选项回弹，不停留在按下发灰态（手机粘滞：各 draw 态同一 StyleBox + 松手后清 press）
- [ ] 决定：错题是否 −10（约定先不做）
- [x] 回写 `design.md` §5.1

## 2. 反向反应 · Go/No-Go

**规格：** `design.md` §5.4 · `scripts/GoNoGo.gd`  
**现状：** 绿点红停；显示随连对 **1.0→0.55s**；间隔 **0.35–0.6s**；Go ≈62%；连对 **6–9** 次窗口内规则反转（每次随机 `flip_at`）。

- 空档与 No-Go 比例已收紧；实机再看是否还需可见「距反转」倒计时。

**改进方向**（已落地）

- Go 比例 → **≈62%**。
- 反转窗口 **6–9** 连对。
- 显示时间随连对 **1.0→0.55**。

- [x] 缩短间隔
- [x] 提高 No-Go 比例
- [x] 更早 / 更可预期的规则反转

## 4. 中间箭头 · Flanker

**规格：** `design.md` §5.9 · `scripts/Flanker.gd`  
**现状：** 1.15→0.52s，不一致 55→82%，间隔 0.22s。十关里最符合检查单的街机。

**问题**

- 手感太像加速版色字。
- 三命：刚加速完容易死。
- 下限 0.52s 时 burst 会盖住箭头。
- 五支箭头一样大，中间不够「中间」。

**改进方向**

- 中间箭头略大或略亮（不要描到变成「看金色」）。
- 命改为 60 秒一局或 5 命。
- 加速后关掉大字 burst，只留中间变色 + 短闪。
- 封顶后再加一档：7 支箭头，或侧翼间距缩小。仍是 Flanker。

- [ ] 中间箭头可辨，但不靠描边作弊
- [ ] 加速后减弱 / 关掉 burst
- [ ] 结束条件：计时局或加命
- [ ] 可选：7 箭 / 更挤的侧翼
- [ ] 回写 `design.md` §5.9

## 5. 舒尔特方格

**规格：** `design.md` §5.2 · `scripts/Schulte.gd`  
**现状：** 数字格 5×5 点完上 6×6，再上 7×7；每档单独计时、单独最佳。格子中途不换位。点错不中断。本地记住档位，再进用进度门继续或从 5×5 重来。动物剪影切块已撤掉。4×4 呼吸关、限时模式未做。

**问题**

- 7×7 之后封顶仍在：熟了只跟自己的秒数比。先用格子变多把技能原子抬一档。
- 点错不中断是对的（保心流），没有额外惩罚。

**改进方向（只加搜索难度）：**

- 通关后出现 6×6、7×7；或完成 5×5 给一局 4×4「我变强了」，再上 6×6（锯齿）。
- 格子必须保持不动。微微换位会变成 MOT，禁止。
- 可选：限时点完（如 40s），失败重排，而不只刷最快纪录。

- [x] 5×5 之后的下一档（6×6、7×7）+ 进度门
- [ ] 可选：通关后的呼吸关 4×4
- [ ] 可选：限时模式
- [x] 回写 `design.md` §5.2

## 10. 汉诺塔

**规格：** `design.md` §5.10 · `scripts/Hanoi.gd`  
**现状：** 3→6 盘，最优才加盘，非最优也能过；记住关数。

**问题**

- 3 盘几乎没 Challenge。
- 非最优可过 → 可以一直混，计划被绕开。
- 6 盘 63 步是**解谜心流**，不要用街机节奏衡量，也不要改成限时闪电手。
- 6 盘后半有 Submission（耗着）风险，可接受，用「堵住混过」解决，不用随机失败。

**改进方向**

- 步数超过最优 ×1.5：**不能算过关**，必须复位重来（或强制不进下一盘）。
- 最优通关后可展示路径（反馈）；玩的时候不要提示下一步。
- 不要加成败随机、不要限时。
- 有存档时进最新关，已经做了。

- [ ] 非最优超步数不能混过
- [ ] 可选：过关后展示最优路径
- [ ] 不加限时、不加随机
- [ ] 回写 `design.md` §5.10

## 改完一关的收尾

**改了哪一关，合入前必须打开本页该关一节，对照代码过一遍。** 不要等「大改手感」才更新。

1. 更新动手顺序表里该关的「状态」一句。
2. 更新本节对应关的「现状」、检查项，以及勾选（做了的勾，没做的保持空）。顺手加的 UI / 存档 / 时限也要写上，不要只记最初那张改进清单。
3. 回写 `design.md` 该关规格（数值以代码为准）。
4. 若改了结束条件（三命 → 计时局），同步 help 文案。
5. 不在本页发明新范式；要换关走 `design.md` 第 1 节「宁可换关」。
